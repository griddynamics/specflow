# Rule catalogue

Every rule is an error. Ids are the names used in config and in findings. "Always" means the rule
needs no project fact and is on in its preset; "Option" names the option that turns it on or
supplies its facts (see `kit.config.example.mjs`). Paths are globs relative to `root`.

Presets: `node` (plain `.js/.mjs/.cjs`), `app` (React + TanStack + Vitest application), `library`
(TypeScript package without React), `e2e` (Playwright specs). A preset is on unless its option is
`false`; `library` is on only when given.

| `--max-warnings 0`                                      | A warning fails the run                                                                                                                                                                                                                                                       | Zero baseline                                                                                                              |

| `eslint-config-prettier` (last)                         | Turns off rules that conflict with Prettier                                                                                                                                                                                                                                   | Formatting is Prettier's                                                                                                   |

### 1.5 Selector groups (`restrict/<group>`)

Each group is ESLint core `no-restricted-syntax` / `-globals` / `-properties` / `-imports` under its
own rule id, so each keeps its own scope. Bad / good pairs are shortened.

| Group                                                        | Enforces                                                                                                                             | Bad -> good                                                                              |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `syntax-base`                                                | No type-star barrel, no TS `enum`, no non-global `namespace`                                                                         | `export type * from` -> named type exports; `enum` -> union of literals                  |
| `syntax-components`                                          | Components reach the DOM through refs                                                                                                | `document.getElementById(..)`, `.innerHTML =` -> `useRef`                                |
| `syntax-query-key`                                           | Query key arrays live in `*query-keys.ts`                                                                                            | `{ queryKey: ['a', id] }` -> `itemKeys.one(id)`                                          |
| `syntax-router-strict`                                       | No `useParams/useSearch({ strict: false })`; no `as` on router hook results                                                          | validate params instead of casting                                                       |
| `syntax-input-preservation`                                  | Entered input is not cleared in the same block as an un-awaited `mutate()` or an `on*` hand-off                                      | reset in `onSuccess` or after `await mutateAsync`                                        |
| `syntax-timer-literal`                                       | No literal delay in `setTimeout/setInterval` or a `use*Debounce*` call                                                               | read the duration from configuration                                                     |
| `syntax-locale-parse`                                        | No `parseFloat` / `Number(e.target.value)` outside locale modules                                                                    | use the locale-aware parser; `localeModules` lists the exceptions                        |

## 3. semgrep

Rules in `semgrep/*.yml` run by default; fixtures in `semgrep/fixtures/` named like the rule file.
Test files (`*.test.ts(x)`) are excluded. `banned-terms.yml` is generated from a terms file (the example build lives in `semgrep-ds/` for the self-test; the rule is OFF until the project builds its own into `<project>/semgrep/banned-terms.yml`), and the
design-system rules (`ds-*` files, built into `semgrep-ds/` from the example facts for the
self-test) are generated from a facts file and OFF until the project supplies it (see
"Configurable rules"); the other files take no project fact. Add the project's own rules in a
`semgrep/` folder at the project root.

### Design-system rules (`ds-*.yml`)

These assume the adopter has a shared primitives layer, and they are OFF until the project
supplies its facts: `run.mjs` loads none of them by default. The project passes its facts file
with `node run.mjs --design-system <facts.json>` (built into a temporary folder for the run) or
builds the files into its own `semgrep/` folder with
`node scripts/build-ds-rules.mjs <facts.json> <project>/semgrep`. The files are generated from
`templates/ds-*.yml.tmpl` and a design-system facts file (`design-system.example.json`) that names
the project's primitives folder, component names, field names, geometry modules, tokens and
classes; never edit the generated files. The kit's `semgrep-ds/` folder is the build of the
example facts and serves only the self-test.

### banned-terms.yml (generated)

`no-project-specific-string` (regex): fails on any configured literal term or pattern in non-test
code. Built by `scripts/build-banned-terms.mjs`; never edited by hand. The shipped example build
is `semgrep-ds/banned-terms.yml`, which `run.mjs` never loads; the generated rule excludes its own
`banned-terms*.json` / `banned-terms*.yml` files.

## 4. knip (`knip.json`)

Every issue type is an error: `files`, `dependencies`, `devDependencies`, `unlisted`, `binaries`,
`unresolved`, `exports`, `nsExports`, `types`, `nsTypes`, `enumMembers`, `duplicates`.
`ignoreExportsUsedInFile` is on and `**/fixtures/**` is ignored. Edit `entry` and `project` to the
project's entry points and sources; add dependencies that are used only by tooling to
`ignoreDependencies` (the template lists `prettier`).

## 5. TypeScript (`tsconfig.base.json`, `tsconfig.library.json`)

Base: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitReturns`,
`noFallthroughCasesInSwitch`, `noUnusedLocals`, `noUnusedParameters`, `noImplicitOverride`,
`noPropertyAccessFromIndexSignature`, `verbatimModuleSyntax`, `erasableSyntaxOnly`,
`noUncheckedSideEffectImports`, `forceConsistentCasingInFileNames`, `allowUnreachableCode: false`,
`allowUnusedLabels: false`, plus `ESNext` target and module, `bundler` resolution,
`isolatedModules`, `moduleDetection: force`, `noEmit`, `skipLibCheck`. A project adds `lib`,
`jsx`, `types`, `include` and path aliases. Library: adds `declaration`, `declarationMap` and
`isolatedDeclarations` so exported declarations state their types.

## 6. Prettier

`.prettierrc`: semicolons, single quotes, trailing commas everywhere, width 100, 2 spaces,
always-parenthesised arrows, LF. `.prettierignore` is the kit's own (it skips semgrep fixtures, the
generated rule files, the templates, `node_modules` and `.venv`). For a project, `run.mjs` uses the
project's `.prettierignore`, else its `.gitignore` plus `prettierignore.project` (build output,
dependencies, reports).

## 7. Size Limit

`size-limit.config.mjs` defines two Brotli budgets: entry JavaScript (module scripts and
modulepreloads read from `dist/index.html`, so the list follows the build) and total JavaScript
(every `.js` under `dist`). Env: `SIZE_LIMIT_DIST`, `SIZE_LIMIT_ENTRY_JS_B`,
`SIZE_LIMIT_TOTAL_JS_B`. Non-numeric budgets are refused. Needs a build first.

## 9. Clone detection and unused CSS

This track's duplication signal comes from `sonarjs/no-duplicate-string` (threshold 5) and the

## Configurable rules

There are no separate `schema-specific/*.md` specs: every configurable check reads its facts from
an option of `defineKitConfig`, or from a small input file built as described here. The complete
neutral example is `kit.config.example.mjs` (an orders application).

Two kinds of option exist, and the `Default` column says which one a check is:

- Path facts (layers, `apiDir`, `apiClient`, `storage`, `entryPoints`, `router`, `localeModules`,
  `components`, `pages`, the e2e folder) default to the conventional layout under `src`. The
  checks that read them are ON without any option; set the option when the project's layout
  differs.
- Data and design facts (type-only packages, wire types, mutation feedback, raw metrics, served
  verdicts, localisation, `designSystem.*`, the banned-terms file, the semgrep design-system facts
  file) have no sensible default. The checks that read them are OFF until the option is set.
