# Configuration

Every setting is an environment variable. A few storage settings can also come from a
cloud profile file. This page lists all of them.

Classes used below:

- **K** - keep: the deployment must set it. It is in `.env.example` with an empty value.
- **D** - default: the code has a default. Set it only to change the default.
- **C** - cloud profile: comes from the cloud profile file; an environment variable overrides it.
- **L** - local: set by `docker-compose.yml` and the `Makefile` for the local stack, or generated by `make env-local`.

Services: **api** (HTTP API), **worker-parse** and **worker-agents** (Temporal workers),
**mcp** (MCP server), **frontend** (Next.js app), **tools** (examples and live tests).

| Name | File key | Meaning |
|---|---|---|

| `AWS_REGION` | `services.object_storage.s3.region` | `s3` only. Unset = the AWS client chain. |
| `STORAGE_S3_ADDRESSING` | `services.object_storage.s3.addressing` | `auto` (default) or `path`. |

## Cloud profile file

Set `SPECFLOW_CONFIG_FILE` to the path of a YAML file. If it is unset or blank, only the
environment is used. Precedence, highest first: environment variable, profile file, default.

```yaml
cloud: gcp | aws | local        # required
services:
  object_storage:
    provider: gcs | s3           # optional; default by cloud
    bucket: your-bucket-name
    prefix: prod/
    s3:  { endpoint_url: null, region: eu-west-1, addressing: auto }
    gcs: { project: null }
```

The file has no secrets. An unknown key, an unreadable file or an invalid value stops the
start-up; the message names the key or variable, never a value. Examples:

- `config/examples/cloud.gcp.yaml` - a Google Cloud Storage bucket.
- `config/examples/cloud.aws.yaml` - an S3 bucket. Add a bucket lifecycle rule `AbortIncompleteMultipartUpload` to remove failed uploads.
- `config/cloud.local.yaml` - the local stack (RustFS). `docker-compose.yml` and the `Makefile` point `SPECFLOW_CONFIG_FILE` at it.

S3 keys come from the standard AWS credential chain. A bucket is never created by the app.

## Local stack

Run `make env-local` first: it writes `.env.local` (git-ignored) with random local secrets, including the
password and id of your local sign-in user. Then it asks for your sign-in email (`LOCAL_TEST_USER_EMAIL`; Enter takes
`git config user.email`; with no terminal it uses `dev@example.com`) and for `AGENT_MODEL`, `LLM_GATEWAY_URL` and
`LLM_GATEWAY_API_KEY` (the key without echo; with no terminal it lists the missing names instead). It writes
`AUTH_ALLOWED_EMAIL_DOMAINS` as the domain of your email plus `example.com` when the name is missing. It never
overwrites or prints a value, so run it again after an update: it appends a missing or empty secret and asks only for
a missing email or missing LLM settings. A secret appended to a file whose volumes already hold data does not match
them: run `make down-volumes` once. `make up` then starts postgres, neo4j, RustFS (S3-compatible,
host port `RUSTFS_HOST_PORT`, default `19000`, bucket `specflow-local`), keycloak (the identity provider of the
whole stack, `127.0.0.1:8180`, realm `specflow`), api, mcp (the MCP endpoint on `127.0.0.1:8002`), worker-parse,
worker-agents and frontend. `make up` stops before compose when `.env.local` lacks a Keycloak value
(`KEYCLOAK_ADMIN_PASSWORD`, `KEYCLOAK_QA_PASSWORD`, `KEYCLOAK_WEB_CLIENT_SECRET`, `LOCAL_TEST_USER_EMAIL`,
`LOCAL_TEST_USER_PASSWORD`, `LOCAL_TEST_USER_ID`) and names the missing ones. `docker-compose.yml` and the `Makefile`
set the local values below.

Keycloak is not optional and has no data volume. Every container creation imports
`config/keycloak/specflow-realm.json`, with the `${NAME}` placeholders filled from `.env.local`: your user (the fixed
id from `LOCAL_TEST_USER_ID` keeps your `sub` stable), the QA users `alice@example.com`, `bob@example.com` and
`carol@other.example` (fixed ids, password `KEYCLOAK_QA_PASSWORD`) and the `specflow-web` client secret. Keycloak
sessions end when the container is recreated. See [local stack](mcp-server/deployment.md#local-stack).

Temporal and Langfuse are optional. The default stack starts neither: the app uses your own.

| Mode | Command | `TEMPORAL_ADDRESS` in the containers | Langfuse in the containers |
|---|---|---|---|
| Own Temporal and Langfuse (default) | `make up` | `TEMPORAL_ADDRESS` from your shell or `.env.local`, else `host.docker.internal:7233` | `LANGFUSE_BASE_URL`, `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` from your shell or `.env.local`; empty = no tracing |
| Bundled Temporal | `make up WITH=temporal` | `specflow-temporal:7233` | as above |
| Bundled Langfuse | `make up WITH=langfuse` | as above | `http://specflow-langfuse-web:3000`, keys from `.env.local` or the local defaults |
| Both | `make up WITH=temporal,langfuse` | `specflow-temporal:7233` | as the row above |

`WITH` sets the compose profiles `temporal` (the dev server) and `langfuse` (web, worker,
postgres, clickhouse, redis, minio). `WITH=keycloak` is refused: Keycloak always starts. `make down`, `make ps` and
`make logs` always cover every profile. Set `TEMPORAL_ADDRESS` to an address the containers can reach (not `localhost`). The host
tools (`make api`, `make worker`) use `TEMPORAL_ADDRESS`, default `localhost:7233`.

The app never creates the Temporal namespace (`TEMPORAL_NAMESPACE`, default `specflow-local`).
The bundled Temporal creates it on start. On your own Temporal, create it once:

```shell
temporal operator namespace create --address <host>:7233 --namespace specflow-local
```

### Removed names

`AUTH_MODE` is not a setting any more: the API, the MCP server and the web app always use OpenID Connect. A value
`AUTH_MODE=dev` in the environment stops the API, the MCP server and the web app with a line that names
`AUTH_MODE` and says to delete `AUTH_MODE` and `AUTH_DEV_SIGNING_KEY` from your env file. Only host runs see it (`make api`, `make frontend-dev`); compose does not pass it on. Both ignore the case of `dev` and surrounding spaces. Any other value is ignored,
so a deployment that still sets `AUTH_MODE=oidc` keeps starting. `AUTH_DEV_SIGNING_KEY` and the old
`MCP_AUTH_*` and `MCP_OIDC_*` compose variables are not read: delete them from `.env.local`. If you used the dev
login before, see [Upgrading from the dev login](../QUICKSTART.md#upgrading-from-the-dev-login).

### Web app on the host

`make frontend-dev` runs the web app on the host against the stack from `make up`. It needs the sign-in values in
`.env.local`, because compose does not pass them to a host process. Stop the `frontend` container first (same port).
Set these names, with the values the compose frontend gets:

| Name | Value |
|---|---|
| `APP_ENV` | `local` |
| `PUBLIC_URL` | `http://localhost:3001` (the realm accepts only this address, or the `PUBLIC_URL` that compose got) |
| `API_INTERNAL_URL` | `http://127.0.0.1:8000` |
| `OIDC_ISSUER` | `http://localhost:8180/realms/specflow` |
| `OIDC_CLIENT_ID` | `specflow-web` |
| `OIDC_CLIENT_SECRET` | the value of `KEYCLOAK_WEB_CLIENT_SECRET` |

`OIDC_INTERNAL_URL` is not needed on the host: it reaches Keycloak on `localhost:8180`. `SESSION_SECRET` is already in
the file.

End-to-end test helpers also read `E2E_DEMO_BASE_URL`, `E2E_PRODUCTION_BASE_URL`,
`E2E_ENV_FILE`, `E2E_OUT`, `E2E_UV` and `PARITY`; they are test-only.

## Document source identity

`DRIVE_IDENTITY_EMAIL` is the e-mail address of the identity that opens the shared
folders. Share each folder with this address. If it is unset or blank, document
source calls fail with `setup_error` and the log event `drive.identity.missing`; there is
no fallback to other credentials. The app still starts.

## Document parsing

Uploads and Drive files are turned into Markdown by the `worker-parse` service with Docling. There
is no setting for the engine, the formats or the limits: they are fixed in the code and described in the
[file parsers documentation](file-parsers/INDEX.md):

- [accepted formats and upload caps](file-parsers/formats.md#accepted-formats);
- [parse limits](file-parsers/limits.md#parse-limits) and [error codes](file-parsers/errors.md#error-codes);
- [time limits](file-parsers/runtime.md#time-limits): one parse runs at a time per `worker-parse` replica, so
  add replicas for a backlog;
- the [deploy order](file-parsers/runtime.md#deploy-order) of `worker-parse`, `worker-agents` and `api`.

### The worker-parse image

- `backend/docker/worker-parse/Dockerfile` builds the only image that holds Docling, PyTorch (CPU wheels),
  OpenCV and the layout and table models. The api and worker-agents images do not contain them and
  never contain PyMuPDF. `make images` builds the four images.
- Size it at 2 vCPU and **3 GiB** (`mem_limit: 3g` in `docker-compose.yml`). A parse works through a PDF in ranges
  of 10 pages; the measured peak is gate G5 in
  [acceptance-gates.md](file-parsers/acceptance-gates.md#status). `/tmp` is a 1 GB tmpfs that counts against
  that limit; the root filesystem is read-only; the process runs as uid 10001.
- Give it a termination grace period of 150 s; running parses finish for up to 130 s after SIGTERM.
- Egress is not needed: the models are baked into the image and nothing is downloaded at run time.

The image sets these variables. Do not change them in a deployment.

| Name | Image value | Meaning |
|---|---|---|
| `HF_HUB_OFFLINE` | `1` | Hugging Face downloads are off; Docling reads only the baked models. |
| `DOCLING_ARTIFACTS_PATH` | `/opt/docling-models` | Folder of the baked models. For tests and development on a host, run `make models`: it fetches them into `backend/.docling-models`, which the tests pick up. |
| `MALLOC_ARENA_MAX` | `2` | Keeps the memory of a long parse flat. |
